## 一、四个"事实":不要把它们混为一谈

| 事实 | 例子 | 能否据此宣称"成功" |
| --- | --- | --- |
| 数据库已提交 | 最外层事务成功提交 | 只证明该数据库连接上的写入；`save!` 返回时外层可能未提交 |
| 入队已请求 | `perform_later` 返回 job 对象 | 可能仍等待提交；同步拒绝可返回 `false` 或抛错误，持久性取决于适配器 |
| 任务已执行 | worker 跑完 `perform` | 不说明外部效果一定发生 |
| 外部效果已确认 | 支付网关回显、回读到远端状态 | 才可对用户或审计说"已完成" |

响应与审计只报告**有证据确认**的阶段。开发环境的 async/test adapter 通过,不证明生产队列可消费。

## 二、异步任务契约

- **幂等靠持久不变量和外部幂等键**,不靠"并发限制"或"continuation"。任务可能重复投递、执行中断、旧任务遇到新代码,每种都要有明确结果。
- **关键工作要有可恢复的持久意图**:先在同一事务里写 `pending` 状态,任务负责推进,补偿扫描负责兜底。没有需求证据时不新建 outbox 表,复用已有状态与补偿入口。
- **重试**只覆盖暂时性故障,设次数、等待与终止策略;写请求超时可能已生效,须用幂等键或回读确认,不能直接重发。
- **参数**必须可序列化;GlobalID 记录可能已被删除,决定忽略、失败还是补偿。
- **批量入队**(`perform_all_later`)可能跳过单任务回调、返回值也不同,采用前检查适配器和版本行为。
- **邮件任务**的继承链和异常处理单独确认,不要假设 `ApplicationJob` 的配置自动覆盖框架任务。
- 队列后端、监听队列、worker 存活、延迟与失败观察入口,交付时要能说清。

### 贯通案例：一次全额退款

[可执行示例](../scripts/examples/refunds.rb) 由 [PostgreSQL 测试](../scripts/postgres_test.rb) 直接使用；仅示范单库、正金额支付的单次全额退款，不覆盖分次退款、跨币种或支付冲正。状态含义如下：

| 退款状态 | 事实与下一步 |
| --- | --- |
| `none` | 未产生退款意图，未付款取消不得触发网关 |
| `pending` | 取消事务保存了支付 ID、金额、币种与稳定幂等键，可派发 |
| `unknown` | 调用超时或回执不确定；先按键查询，不当成失败或成功 |
| `done` | 已确认远端回执并保存本地结果，重复执行直接返回 |
| `failed` | 网关确认永久拒绝，保留人工处理入口，不自动重试 |

`cancel!` 在行锁内写状态、退款快照与审计，再注册事务的 `after_commit`。入队只是加速器，周期扫描 `pending/unknown` 是恢复入口；即使进程在提交后、入队前退出，意图仍存在。已取消的重复请求按本例契约拒绝，不再次创建退款意图。

网关适配器必须实现：同键同支付/金额/币种的并发请求原子去重；同键异载荷拒绝；查询返回确认的回执、明确可安全提交的 `:not_found`，或抛 `UnknownOutcome`。不确定时不能返回 `nil` 后让调用者盲目退款。幂等保留期须覆盖恢复窗口，超期或查询不可靠时转人工核对，不生成新键重放。

进程可能在远端生效后、本地标记前退出；即使本地仍为 `pending`，稳定幂等键也必须阻止重复效果。退款执行入口拒绝调用者已有事务，外呼不持有数据库锁，晚到的超时仅把 `pending` 改为 `unknown`，不能覆盖另一 worker 的 `done`。如果网关不提供这种幂等保证，应另行设计对账/人工恢复，不声称本示例具备 exactly-once 保证。

示例扫描逐条入队，适合演示恢复不变量；实际部署复用已有调度，设置退避、扫描频率、吞吐上限、长时间 pending/unknown 告警和人工处理阈值。适配器异常白名单按真实后端补齐；未知入队异常可以上报，但不能让调用者误以为已经提交的取消被回滚。测试使用受控网关替身，不证明真实支付协议或生产队列可用。

## 三、快照同步与任务所有权

### 全量快照同步

1. 取得**完整**远端快照(验证分页一致性、行类型、身份唯一性、父子引用),再替换本地状态;缺页或非法字段**不能**触发"缺失项清理"。
2. 合法的空快照是否允许清空旧数据,取决于协议和产品策略,不能一概而论。
3. 慢 I/O 放在记录锁外;短事务内重新读取并复核关联身份、配置版本或同步代次,再写入和清理。只校验身份不能证明数据仍是最新;可能有旧响应晚到时,还需要版本或所有权条件。
4. 统计在提交后累计;总体结果区分成功、跳过、失败。

### 任务所有权(原子领取)

<!-- example: sync_run -->
```ruby
class SyncRun < ActiveRecord::Base
  class ClaimLost < StandardError; end

  def self.claim(id, token: SecureRandom.uuid)
    updated = where(id: id, state: "pending")
              .update_all(state: "running", claim_token: token, claimed_at: Time.current)
    updated == 1 ? token : nil          # 只有拿到 token 的执行者可以写结果
  end

  def finish!(token, result)
    updated = self.class.where(id: id, claim_token: token, state: "running")
                  .update_all(state: "done", result: result)
    raise ClaimLost, "sync run #{id} 的领取已失效" unless updated == 1   # 租约过期被他人接管时,旧执行者不能覆盖
  end
end
```

- 领取在短事务/单条原子更新里完成;锁获取失败、重复投递、旧 worker 的 `rescue/ensure` 都不能覆盖其他执行者的状态。
- 远端写入开始后连接中断 = **结果不明**:保留该状态,按幂等协议或回读证据恢复,不凭"没收到回显"就重放。
- 通知是独立结果:发通知失败不能逆转已确认的业务效果。恢复循环除捕获异常外,还要处理接口明确返回的失败值。

## 四、普通 Ruby 的外部 I/O

- 对实际使用的 HTTP、socket、文件、子进程适配器明确**连接/读/写超时、响应大小、整体耗时预算**。优先用适配器原生超时,不要把整个业务事务包进异步打断式 `Timeout.timeout`。
- 多阶段 I/O 使用同一个**单调 deadline**(`Process.clock_gettime(Process::CLOCK_MONOTONIC)`),把剩余预算传给每一步;收到进度或分页不能无限重置超时。
- 重试仅针对已识别的暂时故障,并设次数和总预算。
- 字节与文本分开处理:二进制不套文本编码;`force_encoding` 只改标记,`encode` 才转码且可能失败;替换非法字符必须是业务允许的显式策略;大小限制说明是 `bytesize` 还是字符数。
- 本地文件替换:目标目录写临时文件 → 设权限 → flush/fsync → `rename`;失败保留原文件并清理临时文件。`rename` 的原子可见性不等于多写者仲裁,也不自动保证断电后目录项持久。
- 批处理:限制 worker 数与结果内存;线程异常必须被主流程观察;非关键观察回调失败要隔离并汇总,不能丢掉已产生的业务产物;空任务集用明确状态表达,不要无意继承 `[].all?` 的 `true`。

## 五、缓存与请求状态

- **缓存 key** 包含真正影响结果的身份/租户、locale、过滤条件和数据版本;缓存不能绕过实时授权。
- 缓存原始值或 ID,不缓存 ActiveRecord 实例和可重载的类对象。
- 失败、空结果与"未知"是否缓存必须明确——**不要把超时写成"无数据"**。
- 按业务允许的陈旧程度设置过期和失效,更新/删除要考虑关联结果;不要为一条脏缓存清空整个共享缓存。
- `Rails.cache` 的锁不是分布式业务互斥锁。
- 请求级 locale 用 `I18n.with_locale` 作用域恢复。
- Cable 广播不是离线事件存储,关键界面重连后从持久状态恢复;Active Storage 的 signed URL 不代替租户/对象授权。

## 六、运行证据

- 数据库连接需求按进程、线程、web/job/cable 合计;连接池超时先查泄漏、长事务、负载,不要只增大 pool。
- CPU、内存、尾延迟、吞吐、队列等待一起看;CRuby/Puma 的经验值不当作所有运行时的通用答案。
- 观测优先复用 Rails 日志、`ActiveSupport::Notifications` 与 error reporter。事件描述业务阶段和关联 ID,敏感参数不进载荷。`Rails.error.handle` 会吞错;需要传播失败时选择明确重抛的路径。
