# 评审与自检清单

用于评审他人改动,也用于提交前自查。按改动涉及的层选读,不必逐条打勾。每条都写成问句:未知项按风险查证，不为无关层强补流程。

评审输出格式:**位置(文件:行)→ 问题 → 影响 → 修复方向**。区分"必须修"(正确性、安全、契约)与"建议"(可读性、风格)。

## 一、契约与正确性

- 输入、输出、失败、副作用四项是否都有明确答案?公共方法的调用者是否都检查过?
- `false` / `nil` / 缺失 / 非法输入是否被区分?有没有 `||` 默认值、`to_i`、`!!`、`compact` 把非法值变成合法值?
- 返回值在成功、失败、无结果三种情况下是否一致?末尾新增的日志或赋值是否改变了隐式返回?
- 保持行为的重构:公共方法名、参数(位置/关键字/块)、返回、异常是否不变?有没有夹带功能变更或整仓格式化?
- 是否依赖了目标 Ruby/Rails 版本不支持的语法或 API?

## 二、Ruby 层

- 名字是否揭示意图(领域名词/动词)?有没有 `Manager`/`Processor`/`Helper`/`data`?谓词是否返回布尔?`!` 是否真的表示更危险?
- 方法是否在同一抽象层次?守卫子句是否代替了深嵌套?可选布尔参数是否用了关键字?
- 集合:`map` 里有没有副作用?`filter_map` 是否误丢了 `false`?有没有在遍历中改集合?`Hash.new([])` 共享默认值?
- 异常:是否只捕获具体异常并缩小 `begin` 范围?有没有吞错、破坏清理后重抛或异常脱敏契约?重试是否有上限且仅对幂等操作?
- 资源:块形式或 `ensure` 释放了吗?`ensure` 里有没有 `return`?
- 字符串与正则:整串校验用了 `\A\z` 吗?`force_encoding` 与 `encode` 是否被混用?
- 可变状态:有没有原地修改传入参数、共享的 `@@` 变量、进程级请求状态?

## 三、元编程

- 为什么不能用普通代码?是否走完了阶梯(直接调用 → 组合 → `define_method` → `method_missing` → `eval`)?
- 动态方法名/类名是否来自外部输入?是否经过白名单映射?
- `method_missing` 是否配套 `respond_to_missing?` 并把未处理调用交给 `super`?
- 是否修改了核心类或框架类?能否用 `prepend`、组合、精化替代?加载顺序与作用范围是否写清?
- 动态生成的方法在加载期定义,还是在请求期(会膨胀方法表)?能否 `grep` 到来源?
- 字符串 `eval`/`class_eval` 是否传了 `__FILE__, __LINE__` 且完全不含外部输入?

## 四、Rails 层

- 代码落在正确的层吗(控制器薄、模型持有不变量、Concern 是完整能力、job 的重试/执行边界清楚)?有没有只转发 CRUD 的新层?
- 查找是否从授权范围开始?`params` 是否 `expect`/`permit` 了明确结构?对象可见性、动作与敏感字段是否分别授权?
- `save`/`update` 的 `false` 返回是否处理?应用校验是否有对应的数据库约束(唯一索引、`NOT NULL`、外键)?
- 回调里有没有外部效果(邮件、API、其他聚合)?`update_all`/`insert_all` 等是否说明了跳过什么?
- 查询:有无 N+1?排序是否稳定?`count`/`length`/`size` 用对了吗?动态列名/排序是否走白名单?
- 事务与并发:检查后修改是否有锁/原子更新/约束?事务内有没有网络请求?外部效果是否在提交之后?
- 迁移:是否修改了已共享的迁移?加约束或索引考虑了存量数据、锁与部署窗口?大回填分批了吗?
- 新增自定义 action 是否可以建成资源?`GET` 有无业务写入?
- 视图:输出是否保留转义?有无 `raw`/`html_safe`?文案是否走 i18n?
- 常量命名与目录是否匹配 Zeitwerk?(`bin/rails zeitwerk:check`)
- Hotwire:表单失败是否返回 `422`、非 GET 成功后是否 `303`?Frame/Stream/广播是否做了对象级授权?Stimulus 里有没有业务规则?

## 五、异步、缓存、安全

- 是否把"入队成功""任务执行""外部效果确认"混为一谈?任务是否幂等(持久状态或外部幂等键)?重复投递、旧任务遇新代码怎么处理?
- 重试是否只针对暂时故障并有终止策略?"结果不明"是否被保留而不是盲目重放?
- 缓存 key 是否包含租户/locale/过滤条件/版本?失败和超时有没有被缓存成"无数据"?
- 授权是否覆盖批量、导出、任务、附件、Cable?序列化有没有被当成授权?
- 外部 URL/文件路径/shell 参数是否受控(协议、host、重定向、路径逃逸、argv)?
- 日志、错误报告、job 参数里有没有密钥或敏感字段?

## 六、测试与交付

- 缺陷修复是否有"修复前失败"的回归?新增能力是否覆盖合法路径与拒绝路径(拒绝时确认无副作用)?
- 测试是否针对行为而非实现?数据是否最小?有无外部边界之外的 stub 掉了被测规则?
- 有无依赖执行顺序、真实时间、网络、固定 `sleep` 的不稳定因素?全局状态是否恢复?
- 静态检查、mock、入队断言有没有被当成业务验收?
- 交付说明是否写清:改了什么、为什么、跑了什么(通过/失败/未执行分开)、未验证范围?
- 是否超出已有授权运行了 `db:reset`、`db:drop`、生产迁移或全仓 `rubocop -A`?

## 七、gem、Rake 与脚本

- 公开 API 的改动是否按 SemVer 升了版本?弃用是否先提示、用户看得到(`warn ..., uplevel: 1`)?
- `required_ruby_version` 与实际测试矩阵一致吗?gemspec 文件列表显式且不含夹具、凭据?
- `require` 是否意外启动业务 I/O?有没有修改核心类或全局配置?
- Rake 任务是薄壳吗?破坏性或大批量任务有 `DRY_RUN`、可重复执行、可中断恢复吗?
- 脚本失败时退出码非 0 吗?错误写 stderr 吗?有没有未经确认的 `gem push` 或生产操作?
