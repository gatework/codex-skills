# 安全边界

只检查当前改动涉及的部分,普通格式修改不需要完整审计。具体 API 以目标版本为准。

目录:一、边界规则 · 二、负向用例

异步任务、缓存授权、快照同步与运行证据见 [reliability.md](reliability.md)。

## 一、边界规则

先回答:输入来自哪(浏览器/API/队列/文件/外部服务)?谁能对哪个对象做什么?结果进入哪(SQL/HTML/进程/外网)?

**认证回答“是谁”；授权分别判断可见对象、可执行动作及可修改字段；参数允许列表只限制结构，不赋予权限。** 已授权记录上的关联 ID 也要从允许范围解析，防止把别人的账户/附件挂进自己的记录。

| 边界 | 规则 |
| --- | --- |
| 请求参数 | `params.expect` / `require+permit` 限制形状与可赋值键；另行验证大小、原始类型、枚举和范围；不 `permit!` |
| 外部 JSON/设备响应 | 先验原始类型和完整性再规范化;字符串转数字不能把非法值变成合法的零 |
| SQL | 值绑定;列名、排序方向、结构走受控映射;不要把外部字符串标记为可信 SQL |
| HTML/富文本 | 保留模板转义;富文本用受维护的 sanitizer;不对未信任值 `raw`/`html_safe` |
| JS/JSON/URL | 按输出上下文编码,HTML 转义不能代替所有上下文 |
| Shell | 固定程序 + argv 数组;限制选项/路径;支持时用 `--` 选项终止符;设失败、超时、输出上限;不拼接字符串给 shell |
| 文件 | 从已授权记录取服务器控制的路径;限制大小/类型/处理成本;防路径与符号链接逃逸 |
| 外部 URL(SSRF) | 限制协议、host、端口、重定向和最终解析地址;防内网与云元数据地址 |
| 动态类/方法名 | 白名单映射,不 `constantize`/`send` 原始输入 |

```ruby
# Shell:固定程序 + argv,不经过 shell 解析
system("gzip", "-k", "--", path, exception: true)   # ✓ 每个参数独立;-- 之后一律视为文件名
system("gzip -k #{path}")                            # ✗ 经过 shell 解析,可被注入
```

**会话与浏览器**:沿用现有认证方案,不自制密码加密。验证登录轮换、登出/撤销、闲置与绝对过期、重置凭据有效期、敏感变更重新认证;登录/重置错误不暴露账户是否存在;限流覆盖真实部署的共享状态。`GET` 不触发业务写入;Cookie 会话的写请求保持 CSRF 防护(API-only 不是关闭它的理由,Bearer-only 则按实际凭据模型判断)。CORS 精确配置 origin/方法/credentials,它既不认证用户也不阻止所有跨站写。核对 TLS 代理、可信 host、Cookie 的 `Secure/HttpOnly/SameSite/domain`;开放跳转只接受允许的站内目标。CSP 按真实脚本加载方式设计,report-only 只观察不拦截,不要放开所有 inline script。

**密钥**:来自 credentials/环境注入;不提交 master key;日志、错误报告、URL、构建产物不出现明文。过滤请求参数之后,还要核对自定义日志、job 参数与第三方观测载荷。

**依赖与扫描**:结合当前公告与 `Gemfile.lock` 定向修复并验证;Brakeman、依赖扫描、lint 各自报告结果,不能替代权限测试。

## 二、负向用例

改动涉及权限、输入、任务时,至少覆盖实际威胁,并**同时确认数据库和外部副作用未发生**:

- 其他租户/用户的对象 ID;无权限与低权限角色。
- 非法参数形状(数组代替字符串、嵌套哈希、超长值、越界)。
- 过期或撤销的凭据;无效 CSRF token。
- 下载/导出越权;注入字符(SQL、HTML、shell、路径)。
- 重复提交、重复投递、旧响应晚到。

后台任务需区分“执行时重新授权的用户动作”和“已经接受、必须履行的系统义务”（如退款）：按契约保存主体/租户与意图，避免盲目使用 worker 中的 `Current`，也不要因发起人后来失权就静默丢弃资金处理。

只检查 `200/403` 不足以证明数据范围:同时创建"可见"和"不可见"记录,尝试用筛选参数扩大范围,并从详情入口再验证一次。
