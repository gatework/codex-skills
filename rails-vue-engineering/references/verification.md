# 用证据反驳自己

用于代码审查、修复、重构和 skill 验证。验证的是行为与风险，不是文档中出现了多少关键词。

## 审查流程

1. 固定审读范围，区分当前工作树、提交版本和外部依赖版本。
2. 沿入口、调用者、状态拥有者、失败路径与测试建立假设。
3. 为候选问题寻找现有 guard、不可达条件和反例；源码与需求冲突时不自动站队。
4. 用最小可重复场景确认；不能执行时把推断和待验证项分开。
5. 扫描同类调用形状，但不要把局部发现扩写成全仓已审完。

可靠 finding 写清位置、触发、坏结果、保护为何不足、修复方向及回归证据。优先级依据影响与发生条件；不能因出现“安全”或“数据”就自动判最高级。重构偏好放建议，不伪装成缺陷。

## 测试选择

| 变化 | 优先证据 | 不能证明的事 |
| --- | --- | --- |
| 纯转换、Ruby 语法 | 边界输入、旧新行为对照 | DB/框架集成 |
| Rails 数据与权限 | request/model 与真实目标数据库约束 | mock 查询不能证明锁 |
| 提交后入队 | 外层提交/回滚 + 实际适配器拒绝语义 | 只 stub `perform_later` 抛错会漏掉 `false` |
| 重试与执行所有权 | 成功/失败晚到、重复、崩溃恢复 | 本地 fencing 不证明远端去重 |
| 请求竞态 | 可控制完成顺序的 Promise；断言数据、error、loading | 只测丢弃返回值不证明 callback 没有提前写状态 |
| 草稿与响应式 | 真实编辑路径、选项刷新、同 ID 更新、冲突 | 只检查对象值不证明 DOM 更新 |
| UI | 组件行为 + 浏览器焦点、视口、滚动和关键状态 | typecheck/build 不证明视觉 |

## 并发测试不能靠超时放行来伪装确定性

数据库测试使用独立连接和已提交 fixture；明确每个工作线程进入、等待、释放与退出的信号，收集异常，并保证失败时也释放门闩和清理。

共同锁正确生效后，第二个线程不可能到达锁内的双人 barrier。不要把“等两秒后继续”当作成功路径的同步协议。可以由主线程持锁，让 worker 报告已到达竞争入口，在目标数据库中观察阻塞或明确回调信号，再释放锁并验证第二次检查与最终不变量。超时只用于令挂起测试失败。

证明旧实现会失败时，可在隔离副本中移除 guard 或用对照实现；不要为制造红灯修改用户当前工作树。有限轮询数据库可观察条件与 `sleep` 猜测执行顺序不同，报告实际使用的方法。

## 证据边界

记录命令、目标版本、退出状态、通过/失败/跳过和必要日志位置。测试自身失败、环境不可用与行为缺陷分开。完成 focused 验证和项目适用门禁后停止重复测试；未改业务代码时不为文档交付默认跑全项目发布流程。

skill 文件检查仅证明结构；教学例证明局部语义；按 [场景](../tests/scenarios.md) 自查是自评。只有实际让另一独立 Codex 执行任务并审阅结果，才能称为独立行为验收；在未授权或不可用时明确缺少此证据。
