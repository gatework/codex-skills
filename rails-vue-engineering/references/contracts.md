# 跨层契约与兼容

用于字段、权限、错误、异步动作和部署中的契约变化。不要强制所有 Rails/Vue 项目采用相同 JSON envelope、状态库或认证方案。

## 一次动作走完整链路

**触发**：新增或改变接口与对应页面。

**判断**：列出请求字段、缺失/空值语义、成功与失败结果、授权范围、同步/异步完成方式。类型声明是描述，不是运行时证据。

**做法**：追踪 route → 认证授权 → 参数与领域操作 → DB/任务 → 输出 → API 类型 → 表单/列表 → 用户反馈。改字段时同步真实消费者；UI 模型与 API 不同形时使用局部纯转换，明确哪些转换有损。

**边界**：不要求所有 codec 可逆；格式化、隐藏秘密、服务器默认值本就可能不可逆。稳定错误 code 若项目尚未采用，按真实需要渐进增加，避免重写所有接口。

**验证**：契约测试覆盖 null/缺失、false、错误字段、过期版本、分页、权限、部分成功。异步 UI 不把接受响应显示成已执行。

## 身份、权限与界面能力

**触发**：登录、角色切换、API token、代入、撤销或能力按钮。

**判断**：谁是真实操作者、当前主体、凭证类型和资源范围？权限是否在请求时仍有效？

**做法**：沿项目现有认证与授权入口；后端做最终判断，前端只投影可操作能力。身份变化后使旧请求、缓存、路由与订阅按各自生命周期收敛。旧凭证请求的 401 不应注销已经更新的身份。

**边界**：不能默认所有系统都支持 API token 或代入，也不能直接移植 Motor 的权限键和浏览器会话限制。后端校验不能由前端校验替代。

**验证**：未登录、无权限、错误凭证类型、跨资源访问、撤销、角色变化以及旧响应晚到；审计能区分 actor 与 subject，秘密不进入日志或响应。

## 部署后仍存活的表面

**触发**：重命名、删除、搬迁、状态枚举或协议调整。

**判断**：源码无引用不能证明队列、DB、旧浏览器或外部调用者不再使用它。

**做法**：区分内部符号、持久标识与外部契约。需要时增加有限兼容层，记录切换顺序和退出条件；不以“改完 grep”代替升级测试。生产制品验证后发布同一制品，避免重新构建导致证据失效。

**边界**：没有旧消费者的内部重构可以原子修改；不引入永久 alias，不给小改动附加无关发布流程。部署、提交和外部操作遵循用户已授权范围。

**验证**：旧任务载荷、旧数据、旧前端字段与新后端并存；回滚或前进修复可行；构建、运行与发布制品身份一致。
