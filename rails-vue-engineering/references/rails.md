# Rails 与数据边界

用于 API、Active Record、SQL 和迁移。框架细节查 [来源](sources.md)，并以项目锁定版本验证。

## 解析、授权与持久化校验各司其职

**触发**：接收 HTTP、文件、job 或外部 API 输入。

**判断**：参数允许列表不等于业务验证；类型转换可能抹掉非法输入。先确认缺失、`nil`、`false`、空字符串的合法含义。

**做法**：在入口验证形状与允许值；需要严格整数时先检查契约允许的原始类型，再按十进制解析。资源查找从授权范围开始。输入转换后由领域操作保护业务不变量，数据库保护可表达的持久约束。

**边界**：`params.expect` 仅在目标 Rails 支持时采用；现有 `require/permit` 正确时无需批量替换。可选关联可以用 `find_by`，必需资源按既有 404 语义选择 `find` / `find_by!`。

**验证**：缺字段、错误类型、`false`、跨用户 ID、未授权字段、数据库直接写入及冲突响应。

## 按竞争范围选择并发保护

| 触发与不变量 | 做法 | 不适用条件与验证 |
| --- | --- | --- |
| 单行 read-check-write，需 validation/callback | 在 `with_lock` 内重读、判定、更新 | `with_lock` 自带事务并重新加载；脏对象需明确处理，不能偷偷丢弃。双连接证明第二个执行基于新状态判定。 |
| 简单状态比较和转换 | 条件 UPDATE + 受影响行数 | 批量 API 绕过 validation/callback；显式时间戳，核对版本与审计。测试竞争者恰有一个转换成功。 |
| 用户编辑冲突 | 项目既有 `lock_version` 或版本条件 | 仅加行锁不能发现用户读到旧版本。测试旧表单被拒且保留草稿。 |
| 多行集合替换、全局不变量 | 共同 anchor 或数据库适用的约束/锁 | 所有相关写入口必须参与，锁各自目标行不够。测试不同目标同时修改。 |

`lock!` 不提供包围后续操作的事务，需由调用者建立；`with_lock` 会建立或加入事务。事务保证边界内提交/回滚，不自动串行化任意业务判断。外层事务未结束时，内部块返回不代表锁已释放。

不要把条件 UPDATE 作为所有状态转换的固定风格。数据库的 CHECK 也不能通用地约束跨行总量；选择与实际数据库一致的机制。

## 查询按实际消费方式优化

**触发**：列表、批处理、序列化或性能问题。

**判断**：数据范围、排序稳定性、分页上限、关联读取和查询计划；先测实际规模下的成本。

**做法**：排序列与方向用允许集合；SQL 值绑定不能保护动态标识符。只判断存在可用 `exists?`，只取 ID 可用 `pluck`；列表预加载实际需要的关联。业务批处理采用可恢复进度和有界批次。

**边界**：`exists?` / `pluck` 可能重新查询，不总比已加载集合便宜；`find_each` 有游标与排序语义，不是任意 ordered relation 的等价替代。大表 `count`、offset 或 preload 的成本需实测。

**验证**：授权范围、重复排序值、分页边界、SQL 数量与代表性查询计划；不以少一行 Ruby 判定性能收益。

## 迁移与生命周期

**触发**：改列、状态值、唯一性、删除语义或持久化名称。

**判断**：旧代码、旧任务和历史数据是否会与新版本并存；表规模与锁时间；关联删除是否绕过业务审计。

**做法**：已共享执行的 migration 用后续迁移修正；需要兼容窗口时采用扩展、回填、验证、收缩。大表索引/约束按数据库和 Rails 支持选择在线方式，计划失败重试与前进修复。

**边界**：未共享、明确可重建的项目可沿既有政策整理初始化迁移；纯内部符号不必创造兼容 alias。不要硬编码“下一个发布即可删旧列”，应以旧消费者退出的证据决定。

**验证**：约束拒绝非法数据、旧新代码兼容、回填幂等、schema 与 migration 一致，以及恢复路径。涉及真实数据库验证时先确认隔离环境。
