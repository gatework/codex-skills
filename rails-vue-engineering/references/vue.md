# Vue：请求、草稿与交互

用于 Vue 状态与界面行为；沿用项目实际 Vue、Router、store、HTTP 与 UI 库。不要从另一个组件库的同名组件推断 props 或事件。

## 在写状态前判断请求归属

**触发**：筛选、分页、切换记录、关闭组件、角色切换或并发刷新。

**判断**：结果是否仍属于当前请求和身份？请求函数内部是否已经改写响应式数据？旧请求的 `catch/finally` 是否会清除新请求的状态？

**做法**：请求函数只取结果，由拥有者在 commit 前校验 generation；旧成功、失败和 finally 都不能污染当前状态。生命周期结束或身份变化时 invalidate；能够取消时同时取消以节约资源。

**边界**：AbortController 是资源控制，不是正确性证明，也不能撤销服务器已完成的写入。每行独立 mutation 不应与整页查询共用一个序号；同身份 socket 重连也不一定需要废弃当前 HTTP mutation。

**验证**：分别让 A 在 B 完成前后返回、报错，检查数据、loading 和 error；再验证卸载与身份变化。[随包示例](../examples/latest-request.ts) 演示“检查后同步提交”，不创建第二套 HTTP client。

## 草稿初始化与服务器刷新分开

**触发**：编辑器 watch `visible`、整条 `record`、选项列表；保存失败；附件单独变更。

**判断**：什么事件应丢弃用户输入？同一对象的新引用不一定是新编辑会话。服务器记录、草稿和选项列表是不同状态。

**做法**：打开、明确切换对象或显式放弃时初始化；供应商/字典选项刷新不重置草稿；保存失败保留字段和临时文件。关闭是否保留由产品行为决定，切换对象要处理未保存确认。附件操作只合并其拥有的字段。

**边界**：不能无条件把服务器新 `lock_version` 填入旧草稿，这可能绕过冲突检测。只有确认新版本来自本编辑会话的独立附件操作、且其余业务字段未被他人修改时才采用；外部刷新触发冲突提示或明确 rebase。

**验证**：编辑后刷新选项、同 ID 新对象、删除附件、切换 ID、关闭重开、保存失败和外部并发编辑。既断言输入保留，也断言冲突仍会被发现。

## 根据更新协议选择响应式容器

**触发**：改 `reactive/ref` 为 `shallowRef`、解构 props、优化大列表。

**判断**：内部字段是否通过 v-model 或就地赋值修改？调用者是否依赖深层跟踪？

**做法**：可编辑嵌套对象通常使用深响应式；只按整体替换的不可变结果或外部对象可用 `shallowRef`。普通 `reactive` 的 primitive 属性解构会失去跟踪，使用 getter/toRef(s)。Vue 3.5 的 `defineProps` 解构是编译器特性，不能推广到普通对象。

**边界**：不要把“大”作为唯一理由。shallow 容器内部已是 reactive 对象时行为又不同；必须按实际对象来源判断。明确选择浅层协议时，所有写入口都要遵守替换或显式触发约定。

**验证**：通过用户实际编辑方式检查 computed/DOM 更新，不只检查 JavaScript 对象的值变了。可用 [响应式教学检查](../examples/vue-state.mjs) 观察深浅差异。

## 状态表达与数据新鲜度

**触发**：loading/error/empty 混用，或一个状态机承载多个独立动作。

**判断**：哪些阶段互斥，哪些能同时存在？“有旧数据 + 正在刷新 + 行级提交”可以合法共存。

**做法**：互斥复杂阶段适合判别联合；简单独立 loading 标志仍可使用。旧数据可保留，但要标识刷新失败/过期。查询条件形成一致输入；过滤变化重置页码；影响排序、统计、权限的 mutation 后重新对账。

**边界**：单个巨型联合也会把合法组合变复杂；不强制改写所有布尔值。空数据仅代表成功查询得到零行，不能代替错误或无权限。

**验证**：首次加载、刷新失败、重试、空结果、重复点击、删除末页最后一项，以及两个独立行操作。

## HTTP 与实时流合并

**触发**：初次列表加载与 WebSocket 更新重叠、重连、未读计数。

**判断**：列表是否分页？HTTP 快照是否早于事件？时间戳是否可比较、是否唯一递增？

**做法**：按稳定 ID 去重；用协议提供的 revision/cursor 或本地事件代次识别过时快照，再合并或重取。分页总量由服务端给出；身份变化失效所有旧订阅与请求。

**边界**：当前页长度不能推导全量未读数；任意 ISO 字符串不保证字典序等于时间顺序，同一时间也不能定序。持续事件流下避免无限立即重取，用既有合并/节流策略和可见的新鲜度约定。

**验证**：HTTP 晚到不抹掉新事件、事件重复、分页外事件、重连时 mutation 未完成、旧身份事件晚到。

## 交互完成度

**触发**：新建或改动页面交互。

**做法与依据**：从用户任务组织主次动作，复用设计 token 与组件语义；窄屏保证操作可达；表单错误关联字段，键盘焦点可见，纯图标控件具有可访问名称，文案沿用项目 locale。tooltip 是否提供名称要查组件的实际辅助技术语义。

**边界与验证**：纯样式调整无需顺带重建状态框架。组件测试覆盖行为；真实浏览器检查视口、焦点、滚动、加载/错误及必要主题，静态编译不能证明视觉效果。
